---
title: "错误码"
---

| HTTP 状态码 | 含义 | 处理方式 |
| --- | --- | --- |
| `400` | 请求参数错误 | 检查 JSON 字段、模型名和必填参数。 |
| `401` | 鉴权失败 | 检查 API Key 是否正确、是否带有 `Bearer` 前缀。 |
| `403` | 无权限 | 确认 Key 是否有调用该模型或 API 的权限。 |
| `404` | 资源不存在 | 检查 Endpoint、任务 ID 或模型名。 |
| `429` | 频率限制 | 降低请求频率或联系管理员调整额度。 |
| `500` | 服务端错误 | 稍后重试，并保留请求 ID 方便排查。 |
| `501` | 功能未实现或当前模型不支持 | 检查请求的 Endpoint、协议或模型能力；不要立即重试相同请求。 |
| `502` | 网关无法从上游服务获得有效响应 | 使用指数退避后有限重试；持续失败时记录请求 ID 并反馈。 |
| `503` | 当前请求的上下文过长，服务无法处理 | 缩减 `messages` 中的历史内容或输入长度后重新请求。 |

## 重试原则

- `400`、`401`、`403` 和大多数 `404` 是请求或权限问题，修正后再重试。
- `429` 应降低并发并使用指数退避，例如等待 1、2、4、8 秒后重试。
- `500`、`502` 或网络超时可有限重试。建议使用指数退避，例如等待 1、2、4、8 秒，并限制总重试次数。
- `503` 表示当前上下文过长。删除较早的对话历史、压缩长文本或降低输入长度后再重试；等待后原样重试通常不会解决问题。
- `501` 通常表示请求的功能、协议或模型能力不受支持。应调整请求或选择其他模型，而不是重试相同请求。
- 异步 3D 任务在提交后遇到网络错误时，请优先使用已有外层任务 ID 继续查询状态，不要立即重复提交。
- 反馈问题时，请提供请求时间、HTTP 状态码、请求路径、外层任务 ID 和响应中的请求 ID（如有）。不要提供 API Key。
